# Gesture Language Specification
## Управление Windows, macOS и Android жестами рук

**Версия:** 1.0  
**Назначение:** отдельная спецификация жестов для проекта бесконтактного управления компьютером и Android-устройствами через камеру.

---

# 1. Главный принцип

Основной язык жестов должен быть одинаковым на всех поддерживаемых платформах.

Пользователь запоминает **жест**, а не команду конкретной ОС.

Пример:

- кулак = назад / отмена;
- Windows → `Esc`;
- macOS → `Esc`;
- Android → `Back`.

То есть:

```text
GESTURE
   ↓
MEANING
   ↓
PLATFORM ACTION
```

---

# 2. Принцип сложности

Жесты делятся на три уровня:

1. **Basic / Основные** — обязательный минимальный набор.
2. **Advanced / Дополнительные** — открываются через подсказки и обучение.
3. **Expert / Профессиональные** — сложные, двухручные и контекстные действия.

Пользователь не должен изучать все жесты сразу.

---

# 3. Basic — основные жесты

Это ядро системы.

Пользователь должен освоить их при первом запуске за 1–2 минуты.

| Жест | Рук | Смысл | Windows | macOS | Android |
|---|---:|---|---|---|---|
| ✋ Ладонь удержать ~0,8 с | 1 | Включить / поставить управление на паузу | Active / Standby | Active / Standby | Active / Standby |
| ☝️ Указательный палец + движение | 1 | Наведение | Cursor | Cursor | Virtual pointer |
| 🤏 Короткий pinch | 1 | Выбрать | Left click | Click | Tap |
| 🤏 Pinch + движение | 1 | Захватить и переместить | Drag & Drop | Drag & Drop | Drag / Swipe object |
| ✌️ Два пальца + движение ↑↓ | 1 | Прокрутка | Scroll | Scroll | Scroll |

---

# 4. Basic: логика Pinch

Pinch — основной жест действия.

Система должна различать несколько состояний:

```text
PINCH
 │
 ├── быстрое отпускание
 │      ↓
 │    CLICK
 │
 ├── удержание + движение
 │      ↓
 │    DRAG
 │
 └── удержание без движения
        ↓
      CONTEXT ACTION
```

В Basic обязательны только:

- click;
- drag.

Context Action относится к Advanced.

---

# 5. Basic: активация управления

Открытая ладонь используется как clutch-механизм.

```text
STANDBY
   ↓
✋ удержание ~0,8 с
   ↓
ACTIVE
```

Повторное удержание:

```text
ACTIVE
   ↓
✋ удержание ~0,8 с
   ↓
STANDBY
```

Обычное кратковременное появление ладони не должно включать или выключать управление.

---

# 6. Advanced — дополнительные жесты

Эти жесты не должны преподаваться пользователю все сразу.

Система показывает их через:

- onboarding;
- контекстные подсказки;
- короткие tutorial cards;
- подсказки во время обычного действия.

| Жест | Рук | Смысл | Windows | macOS | Android |
|---|---:|---|---|---|---|
| 🤏 Удержание без движения ~0,7 с | 1 | Контекстное действие | Right click | Secondary click | Long press |
| 🤏🤏 Двойной pinch | 1 | Двойное действие | Double click | Double click | Double tap |
| ✊ Кулак коротко удержать | 1 | Назад / отмена | Esc | Esc | Back |
| 🖐️ 3 пальца + swipe ↑ | 1 | Показать открытые приложения | Task View | Mission Control | Recents |
| 🖐️ 3 пальца + swipe ↓ | 1 | Основной экран | Show Desktop | Show Desktop | Home |
| 🖐️ 3 пальца + swipe ← / → | 1 | Следующее / предыдущее приложение | Alt+Tab | Cmd+Tab | Switch App |
| 🤏 Grab окна + быстрый flick ← / → | 1 | Пристыковать окно | Snap Left / Right | Tile Left / Right | Для оконного режима, если поддерживается |
| 🤏 Grab окна + flick ↑ | 1 | Развернуть окно | Maximize | Full Screen / Maximize | Expand Window |
| 🤏 Grab окна + flick ↓ | 1 | Уменьшить / свернуть | Restore / Minimize | Minimize / Restore | Minimize / Return |

---

# 7. Перемещение окна: Drag vs Flick

Система должна отличать обычное перемещение окна от быстрого броска.

```text
PINCH + MOVE
     │
     ├── низкая скорость
     │      ↓
     │     DRAG
     │
     └── высокая скорость
            ↓
           FLICK
            ↓
        WINDOW SNAP
```

Направления:

```text
←  Snap Left
→  Snap Right
↑  Maximize
↓  Restore / Minimize
```

---

# 8. Контекстная подсказка для окон

При обычном захвате окна пользователь может увидеть подсказку:

```text
          ↑ MAXIMIZE

← SNAP      🤏      SNAP →

          ↓ MINIMIZE
```

Подсказка должна:

- появляться ненавязчиво;
- исчезать автоматически;
- отключаться в настройках;
- не мешать обычному drag.

---

# 9. Expert — профессиональные жесты

По умолчанию могут быть отключены.

Предназначены для пользователей, которые уже освоили базовое управление.

| Жест | Рук | Смысл | Windows | macOS | Android |
|---|---:|---|---|---|---|
| ☝️ ☝️ Две руки расходятся / сходятся | 2 | Масштаб | Zoom | Zoom | Pinch Zoom |
| 🤏 🤏 Две руки захватывают объект | 2 | Изменить размер объекта | Resize | Resize | Resize |
| 🤏 🤏 Две руки + вращение | 2 | Поворот | Graphics / 3D | Graphics / 3D | Rotate |
| 🤏 Grab + flick ↖ ↗ ↙ ↘ | 1 | Разместить окно в четверти экрана | Snap Quadrant | Window Tiling | Desktop / Tablet Mode |
| 🤏 Grab + сильный flick через край | 1 | Перенести окно на другой монитор | Move to Monitor | Move to Display | Необязательно |
| ✋ + специальный жест | 1 | Радиальное меню | System / Apps / Media | System / Apps / Media | Apps / Media / System |

---

# 10. Одна или две руки

Основной принцип:

> Одна рука должна обеспечивать около 90% повседневного управления.

Одна рука:

- pointer;
- click;
- drag;
- scroll;
- back;
- window switch;
- window snap;
- activation.

Две руки использовать только там, где это действительно естественно:

- zoom;
- resize;
- rotate;
- манипуляция крупным объектом;
- 3D / creative workflows.

---

# 11. Ведущая рука

Приложение должно поддерживать:

- Right-handed;
- Left-handed;
- Auto.

Появление второй руки в кадре не должно автоматически переводить систему в двухручный режим.

Двухручный режим активируется только после распознавания соответствующего двухручного жеста.

---

# 12. Поведение второй руки

Если одна рука является ведущей:

- вторая рука может появляться в кадре;
- система не должна терять управление;
- вторая рука не должна случайно вызывать команды;
- при необходимости она может использоваться как modifier-hand.

---

# 13. Аналогия с тачпадом

Часть жестов должна сознательно повторять знакомую механику тачпада.

Рекомендуемая логика:

```text
1 палец  → pointer
2 пальца → scroll
3 пальца → приложения / multitasking
4 пальца → virtual desktops / spaces
```

Четырёхпальцевые жесты можно добавить позднее и не включать в первый MVP.

---

# 14. Будущий четырёхпальцевый уровень

Необязательные жесты:

| Жест | Windows | macOS | Android |
|---|---|---|---|
| 4 пальца ← / → | Virtual Desktop Left / Right | Spaces Left / Right | Необязательно |
| 4 пальца ↑ | Desktop Overview | Mission Control / Spaces Overview | Необязательно |

Эти жесты не входят в обязательный набор v1.

---

# 15. Обучение пользователя

## Первый запуск

Пользователь должен пройти короткий onboarding только по Basic:

1. ✋ Activate;
2. ☝️ Pointer;
3. 🤏 Click;
4. 🤏 + move Drag;
5. ✌️ Scroll.

Цель:

пользователь должен начать управлять системой максимум через 1–2 минуты.

---

# 16. Контекстное обучение

Advanced-жесты показываются только тогда, когда они могут быть полезны.

Пример:

пользователь несколько раз перетаскивает окно.

Система может показать:

> Можно быстро бросить окно влево или вправо, чтобы закрепить его у края.

После этого отображается короткая визуальная подсказка.

---

# 17. Система уровней в интерфейсе

В интерфейсе приложения использовать названия:

```text
Основные
Дополнительные
Профессиональные
```

В коде и документации допустимо:

```text
BASIC
ADVANCED
EXPERT
```

# 18. Visual FX для жестов

Визуальные эффекты должны помогать понимать состояние системы.

## Pointer

На активном пальце:

```text
○
```

## Pinch Prepared

```text
◎
```

## Click

```text
◉ → ◎ → ○
```

## Grab

Замкнутое кольцо:

```text
◉ GRAB
```

## Scroll

```text
  ↑
  │
 ✌️
  │
  ↓
```

## Back / Esc

При кулаке круг быстро схлопывается.

## Activation

Вокруг ладони кольцо постепенно замыкается:

```text
◔ → ◑ → ◕ → ● ACTIVE
```

---

# 19. Visual FX Modes

Жесты должны работать одинаково при любом режиме визуализации.

```text
FULL
MINIMAL
OFF
```

## FULL

- hand outline;
- skeleton;
- gesture indicators;
- trails;
- labels;
- snap zones;
- rings;
- ripple.

## MINIMAL

- active finger;
- pinch confirmation;
- activation state;
- основные snap indicators.

## OFF

- никакой визуализации;
- gesture engine продолжает работать.

---

# 20. Правила распознавания

Каждый gesture должен иметь:

- enter threshold;
- exit threshold;
- hold time;
- cooldown;
- confidence;
- movement threshold;
- velocity threshold при необходимости.

Нельзя строить управление только на одном условии положения пальцев.

---

# 21. Приоритеты жестов

Пример приоритетов:

```text
EMERGENCY / DISABLE
        ↓
SYSTEM STATE
        ↓
TWO-HAND MANIPULATION
        ↓
GRAB / DRAG
        ↓
CLICK / CONTEXT
        ↓
SCROLL
        ↓
NAVIGATION
        ↓
POINTER
```

---

# 22. Принцип отсутствия конфликтов

Один и тот же жест не должен одновременно запускать несколько действий.

Например:

- `pinch + movement` не должен вызывать click;
- `scroll mode` не должен одновременно двигать cursor;
- `flick` должен распознаваться только после grab окна;
- появление второй руки не должно отключать pointer первой руки.

---

# 23. MVP Gesture Set

Для первого рабочего MVP рекомендуется реализовать:

## Basic

- ✋ Activate / Pause;
- ☝️ Pointer;
- 🤏 Click;
- 🤏 + move Drag;
- ✌️ Scroll.

## Advanced

- ✊ Back / Esc;
- 🤏 Hold Context;
- 3 fingers ↑ App Overview;
- 3 fingers ← / → App Switching;
- Grab + Flick Window Snap.

Expert-жесты в первый MVP можно не включать.

---

# 24. Ключевой UX-принцип

Пользователь не должен думать:

> Какой жест сейчас нужен?

Он должен думать:

> Я хочу взять это окно и переместить его.

Жесты должны ощущаться как естественные физические действия:

```text
указать
взять
отпустить
прокрутить
смахнуть
раздвинуть
свести
```

# 25. Итоговая модель

```text
BASIC
│
├── Pointer
├── Click
├── Drag
├── Scroll
└── Activate / Pause

ADVANCED
│
├── Context
├── Back
├── Multitasking
├── App Switching
└── Window Flick / Snap

EXPERT
│
├── Two-hand Zoom
├── Resize
├── Rotate
├── Multi-monitor Throw
└── Radial Menu
```

Основная цель — сохранить маленький, понятный словарь жестов и раскрывать более сложные возможности постепенно.
