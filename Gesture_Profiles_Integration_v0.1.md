# Жесты, профили приложений и экранная клавиатура

Уточнение dev9: открытая ладонь — поза управления, кончик указательного — точка наведения по умолчанию (`pointer_mode=PALM`, `pointer_anchor=INDEX`). Упоминания центра ладони ниже описывают dev8; эта привязка теперь доступна отдельно через `pointer_anchor=PALM`. Удержание открытой ладони в ACTIVE не выключает управление.

Редакция 0.1, 2026-09-17. Дополнение к основному ТЗ редакции 0.3 и `Gesture_Language_Windows_macOS_Android_v1.0.md`, с учётом запроса пользователя о 3D, видеообработке и других программах. Существующий функциональный объём сохраняется.

## Согласование двух спецификаций

| Вопрос | Принятое правило |
|---|---|
| Платформы | Реализация текущего этапа — Windows. Общий язык жестов проектируется переносимым; новый документ сам по себе не запускает разработку macOS/Android |
| Ладонь и пауза | В PALM ладонь включает управление и затем наводит курсор; для паузы — Pause/горячая клавиша. В INDEX сохранено ACTIVE↔STANDBY. Аварийная пауза требует Resume |
| Уровни | BASIC/ADVANCED/EXPERT — уровни обучения и доступности, не разрешение исключать ранее заявленные функции |
| Pinch context | Базовый правый click остаётся отдельным жестом. HOLD_PINCH будет отдельной взаимоисключающей политикой: она требует отложенного левого down до выбора click/drag/context; после уже отправленного левого down нельзя незаметно превращать его в правый click |
| Три пальца без движения | Зарезервированы для вызова клавиатуры. Чтобы сохранить альтернативный правый click без конфликта, его альтернативная поза меняется на pinch большого и безымянного пальцев |
| Swipe | Трёхпальцевые swipe из нового документа — основной план для multitasking; прежний palm swipe остаётся альтернативным назначением, одновременно не активируется |
| Zoom | Новая двухручная поза с указательными пальцами — альтернативный способ явного входа; уже начатый drag не перехватывается двухручным режимом |
| Flick | Только после подтверждённого захвата окна, а не произвольного объекта. Нужен адаптер контекста окна; высокая скорость при обычном drag сама по себе не выполняет Snap |

## Архитектура профилей

`Perception → Gesture → Semantic Action → Application/Platform Adapter → Command Engine → Input`.

Профиль задаёт смысл жеста для текущего контекста, не содержит алгоритм tracking и не выполняет ввод напрямую. Системные активация, пауза, emergency и вызов клавиатуры сохраняют смысл во всех профилях и не переопределяются пользовательской привязкой.

В текущем этапе реализован локальный реестр JSON-профилей с проверкой схемы, уникальности id и допустимых назначений. Есть Desktop и шаблоны 3D/Video; список расширяется добавлением JSON в `gesture_control/profiles`. Переключение Profile/F циклическое и явное. Оно останавливает взаимодействие, освобождает ввод приложения через ControlMachine и требует Resume. Никаких сочетаний для случайно выбранного приложения не отправляется.

Шаблоны 3D/Video описывают намерения: выбор, перенос, масштабирование, вращение, перемещение по таймлайну, воспроизведение. Это не готовые адаптеры Blender, Maya, 3ds Max, Premiere, Resolve или другой программы. Точные команды определяются после выбора программ, версии и раскладки горячих клавиш. Поле `applications` — метаданные для будущего сопоставления с executable; автоматического выбора по foreground window пока нет.

Следующие этапы профилей:

1. Адаптеры конкретных программ: executable, версия/keymap, понятные названия действий, проверка поддерживаемых команд.
2. Редактор пользовательских назначений, проверка конфликтов и возврат к стандартному профилю.
3. Автовыбор по foreground executable с ручной фиксацией профиля. При смене приложения во время drag — освобождение старого захвата, пауза, без переноса ввода в новый контекст.
4. Непрерывные 3D-действия (orbit/pan/rotate/scale) и работа с таймлайном, с единицами чувствительности и отдельной проверкой ложных действий.
5. Отдельный UI-контекст экранной клавиатуры: ввод букв не должен интерпретироваться как 3D-манипуляция или scrub.

## Реализуемая активация

Начальный OFF сменяется на STANDBY после получения свежих кадров и успешной регистрации аварийного hotkey. Запуск `--preview` является явной командой включения камеры. Открытая неподвижная ладонь удерживается 800 мс; одно предъявление даёт одно переключение. Для повторного переключения требуется выйти из позы минимум на 250 мс.

Наведение по уточнению пользователя выполняется открытой ладонью: pointer_mode=PALM, точка управления — центр ладони. В ACTIVE ладонь больше не вызывает паузу. INDEX сохраняет старый способ как настройку. В Desktop также подключён левый pinch и сглаженный drag. При потере выбранной руки ACTIVE переходит в PAUSED с возможностью восстановления одной открытой ладонью после выдержки, допускающей небольшое дрожание. После аварийной остановки, смены камеры, основной руки или профиля нужен Resume.

`Ctrl+Alt+G` регистрируется через Windows RegisterHotKey и обрабатывается отдельным потоком. Вызов остановки сериализован с состоянием взаимодействия через RLock и не зависит от рендера/inference. Ошибка регистрации блокирует активацию. В preview backend остаётся fake; в control отдельный процесс исполняет перемещения и левый down/up, контролирует heartbeat и освобождает принадлежащую кнопку. Реальные жесты click/drag требуют отдельной ручной приёмки.

## Экранная клавиатура

Первая реализация использует встроенную Windows On-Screen Keyboard (`osk.exe`) без собственного механизма ввода текста. Её можно открыть кнопкой Keyboard или клавишей K в preview. В ACTIVE добавлен отдельный системный жест: удержать указательный, средний и безымянный пальцы выпрямленными, мизинец согнутым, примерно 1 секунду. Большой палец для этой позы не учитывается.

Этот неподвижный жест не является трёхпальцевым swipe: движение сбрасывает подтверждение. Удержание не повторяет запуск до выхода из позы. Очередь вызова очищается при pause/profile/camera change. Для этого первого варианта закрытие производится кнопкой X самой Windows-клавиатуры; жест закрытия, собственная клавиатура с крупными клавишами, hover/dwell и раскладками RU/EN остаются развитием функции.

OSK — реальное системное окно, но автоматического ввода букв пока нет. Для бесконтактного выбора букв сначала требуется реализовать курсор/pinch и отдельный keyboard UI context. Ошибка запуска выводится в preview, не завершает приложение. Текст пользователя не перехватывается, не сохраняется и не попадает в логи.

## Приёмка дополнения

- Непрерывное удержание ладони 5 секунд даёт одно переключение; краткое появление не активирует управление.
- PAUSED после аварийной/ручной остановки не снимается позой руки; Resume переводит в STANDBY. Исключение только для потери tracking: одна подтверждённая ладонь восстанавливает ACTIVE без прежнего захвата.
- Аварийная остановка работает при потерянном фокусе preview; отсутствие регистрации не позволяет ACTIVE.
- Профили не меняют системные жесты; неизвестные команды и повторяющиеся id отклоняются.
- Смена профиля/камеры очищает текущие действия; старый запрос вызова клавиатуры не выполняется после смены сессии.
- Keyboard/K открывает OSK; удержание трёх пальцев в ACTIVE даёт один вызов, в STANDBY/PAUSED — ноль.
- Аппаратное распознавание поз и фактический ввод в выбранных программах проверяются отдельно от синтетических тестов.
